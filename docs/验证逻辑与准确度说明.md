# PDF 转 Markdown 验证逻辑与准确度说明

> 文档版本：1.0
> 更新日期：2026-07-29
> 适用项目：PDF 转 Markdown Web 工具 0.6

## 1. 说明目的

本文说明 PDF 转 Markdown 工具当前使用的验证逻辑，并区分以下三个容易混淆的指标：

1. 转换完整性验证。
2. 文本保留相似度。
3. OCR 识别置信度。

当前系统能够自动检查转换过程中是否出现明显遗漏，但不能仅凭这些指标证明 OCR
识别结果或文档语义百分之百正确。

## 2. 整体验证流程

系统按以下顺序处理 PDF：

1. 分析每页是否存在可直接读取的文字层。
2. 有文字层的页面使用 `pypdf` 直接提取。
3. 文字不足的扫描页面使用 PaddleOCR。
4. 将所有页面按照原 PDF 页码组合成 Markdown。
5. 根据用户选择生成完整版本或重点摘要版本。
6. 比较参考文本与最终 Markdown。
7. 输出文本相似度、关键内容保留情况、问题页面和主要改动。

## 3. 转换完整性验证

### 3.1 页码验证

每个 Markdown 页面都会保留类似以下标记：

```markdown
<!-- source-page: 2 -->
```

系统检查：

- PDF 总页数是否与 Markdown 页码标记数量一致。
- 是否缺少某一页。
- 是否存在无法验证或 OCR 失败的页面。

页码映射不完整时，完整转换不能被标记为验证通过。

### 3.2 正文覆盖率

系统分别计算：

- 单页正文覆盖率，要求不低于 80%。
- 整份文档正文覆盖率，要求不低于 85%。

正文覆盖率用于发现整段内容或单独页面被遗漏的情况。

### 3.3 关键事实验证

系统会提取并检查以下内容：

- 数字。
- 日期和时间。
- 百分比。
- 金额。
- 型号。
- 编号。
- 包含数字的参数。

关键事实保留率要求不低于 98%。

### 3.4 关键句验证

系统会重点检查包含以下信号词的句子：

- 必须。
- 禁止。
- 不得。
- 严禁。
- 应当。
- 注意。
- 要求。
- 条件。
- 步骤。
- 期限。
- 参数。
- `must`、`required`、`warning`、`prohibited`、`deadline` 等英文信号词。

关键句要求全部保留；任何一条关键句缺失都会产生警告。

### 3.5 完整转换通过条件

完整转换需要同时满足：

- Markdown 存在可用正文。
- 页码映射完整。
- 没有缺失页、问题页或无法验证页。
- 整体正文覆盖率不低于 85%。
- 每页正文覆盖率不低于 80%。
- 关键事实保留率不低于 98%。
- 关键句保留率为 100%。
- 没有 OCR 失败页。

## 4. 文本保留相似度

### 4.1 计算步骤

系统首先对参考文本和 Markdown 进行标准化：

1. 统一 Unicode 字符格式。
2. 英文字母统一为小写。
3. 去掉空格、标点和其他非文字数字字符。
4. 将文本拆分成连续四字符片段。

例如：

```text
必须在15分钟内处理
```

会拆分为多个连续四字符片段，例如：

```text
必须在1
须在15
在15分
15分钟
5分钟内
分钟内处
钟内处理
```

### 4.2 计算公式

```text
文本保留相似度
= 最终 Markdown 中找到的参考文本四字符片段数
÷ 参考文本四字符片段总数
```

例如，参考文本包含 1000 个不同的四字符片段，Markdown 中找到 930 个：

```text
相似度 = 930 ÷ 1000 = 93%
```

### 4.3 相似度表示什么

相似度可以反映：

- 是否遗漏正文。
- 是否缺少单独页面。
- 摘要省略了多少内容。
- 型号、数字和关键要求是否仍然存在。

相似度不能证明：

- 文本语义一定正确。
- Markdown 排版一定与 PDF 完全一致。
- 表格行列关系一定正确。
- OCR 一定正确识别了图片上的所有文字。

## 5. OCR 页面的验证逻辑

### 5.1 OCR 触发条件

系统先检测每页的可提取文字数量。文字不足的页面会被标记为扫描页或低文字页，
并单独交给 PaddleOCR；有正常文字层的页面不会重复执行 OCR。

### 5.2 OCR 页面参考文本

扫描页不存在可以直接读取的原始文字，因此处理链路为：

```text
PDF 页面图片 → OCR 提取全文 → Markdown
```

验证转换或摘要是否遗漏内容时，系统使用“OCR 提取全文”作为该页的参考文本。

这可以验证 OCR 提取结果是否在后续转换中被保留，但不能独立验证 OCR 最初是否
把图片上的文字识别正确。

### 5.3 OCR 置信度

PaddleOCR 会为识别出的文字返回 `rec_scores`。系统计算这些分数的平均值，作为
该页的平均 OCR 识别置信度。

例如：

```text
识别分数：96%、92%、94%
平均置信度：(96% + 92% + 94%) ÷ 3 = 94%
```

OCR 置信度是模型对自身结果的信心，不是经过人工标准答案验证后的真实准确率。

### 5.4 OCR 自验证的局限

假设图片原文为：

```text
型号 OX-2026
```

OCR 错误识别为：

```text
型号 0X-2026
```

如果最终 Markdown 完整保留了 `0X-2026`，文本保留相似度仍可能达到 100%，
但 OCR 实际已经发生识别错误。

因此，OCR 页面显示的相似度应理解为“后续转换保留率”，不能称为“图片识别准确率”。

## 6. 验证状态

系统可能返回以下状态：

| 状态 | 含义 |
|---|---|
| `complete` | 自动规则没有发现明显遗漏 |
| `incomplete` | 正文、关键事实、关键句或页面可能缺失 |
| `limited` | 缺少可用参考文本或页面映射，无法完成可靠验证 |
| `review_required` | OCR 失败、疑似扫描件未使用 OCR，或存在其他质量风险 |
| `failed` | 没有生成可用内容，或页码映射严重不完整 |

## 7. 如何验证真实 OCR 准确率

要得到真实 OCR 准确率，需要准备人工确认过的标准答案，并使用以下指标：

### 7.1 字符错误率

```text
CER = 插入字符数 + 删除字符数 + 替换字符数
    ÷ 标准答案字符总数
```

字符准确率可以表示为：

```text
字符准确率 = 1 - CER
```

### 7.2 单词错误率

英文文档或已经正确分词的文本可以计算 WER：

```text
WER = 插入单词数 + 删除单词数 + 替换单词数
    ÷ 标准答案单词总数
```

### 7.3 关键字段准确率

对客服知识库文档，建议单独统计：

- 型号完全匹配率。
- 日期和时间完全匹配率。
- 金额和百分比完全匹配率。
- 业务编号和错误码完全匹配率。
- “必须、禁止、不得”等关键要求句的完整匹配率。

### 7.4 表格准确率

表格还需要额外验证：

- 表格是否被识别。
- 行列数量是否正确。
- 单元格内容是否正确。
- 单元格与行列的对应关系是否正确。

## 8. 当前结论

当前系统已经能够自动验证：

- 页面是否齐全。
- 转换过程是否遗漏大段正文。
- 数字、日期、型号和编号是否保留。
- 关键要求和步骤是否保留。
- OCR 是否成功执行。
- OCR 结果是否在后续 Markdown 转换或摘要阶段被保留。

当前系统尚不能仅凭自动相似度验证 OCR 对图片文字的真实识别准确率。真实 OCR
准确率需要使用人工校对样本，通过 CER、WER、关键字段准确率和表格准确率进行
独立评测。
